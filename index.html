1. resp.json() 与 json.dump() 方向相反

操作方向输入输出

  • json.dump 再把字典变回 JSON 写进文件。

2. json.dump(data, f, ...) 每个参数

参数作用
data要写的 Python 对象
fopen() 返回的文件把手，不是文件名
ensure_ascii=False中文原样写，不转 \uXXXX
indent=2缩进 2 格、换行

等价三步：

f = open("team.json", "w", encoding="utf-8")
json.dump(data, f)
f.close()

with open(...) as f: 只是自动关门。

JSON.py

谁能读Python、JS、Excel、手机 App基本只有 Python
读取json.load 解析import 会执行文件
安全只解析可能执行任意代码

网页（复习页 App）只能读 JSON，读不了 .py。

不要猜，先打印：

import time


def fetch(url, timeout=5, retries=3):
    for attempt in range(1, retries + 1):
        try:
            r1 = requests.get(url, timeout=timeout)
            r1.raise_for_status()
            return r1
        except (requests.exceptions.ConnectionError, requests.exceptions.Timeout):
            print("尝试", attempt, "/", retries, "失败")
            time.sleep(1)
    return None

  • 无限等——服务器不响应时程序会卡死。线上代码必须写。

import sqlite3
import csv

cur.execute("CREATE TABLE IF NOT EXISTS sales(id INTEGER PRIMARY KEY,region TEXT,amount INTEGER)")
cur.execute("DELETE FROM sales")           # 幂等
cnn.commit()

with open("sales.csv", newline="", encoding="utf-8") as f:
    reader = csv.DictReader(f)             # 每行变字典，键是表头
    valid = 0
    skipped = 0
    rows = []                              # 先建空列表

    for row in reader:
        try:
            value = int(row["amount"])     # 字符串转整数
        except ValueError:
            skipped = skipped + 1          # 坏值计数
            continue
        valid = valid + 1
        rows.append((row["region"], value))  # 攒元组

    print("有效", valid, "跳过", skipped)
    print(rows)

cur.executemany("INSERT INTO sales(region,amount) VALUES(?,?)", rows)  # 批量插入
cnn.commit()

for region, cnt, total, avg_amount in cur.execute(
    "SELECT region,COUNT(*),SUM(amount),AVG(amount) FROM sales GROUP BY region ORDER BY region"
):
    print(region, cnt, total, round(avg_amount, 1))

cnn.close()                                # 顶格，循环外

  • DictReader 靠表头生成键；值都是字符串；

  • executemany 接收元组列表；

1. 一句话

Git 不是“保存文件”，是让你在三个区之间搬动同一批文件的状态；add 和 commit 搬东西，status/diff/log 只看不动。

2. 一张图

工作区  ──git add──▶  暂存区  ──git commit──▶  提交区（历史）
   │                    │                        │
   │◀─ git restore ─────┤                        │
   │◀─ git restore --staged ─┘                    │
   │                                             │
   └──── git diff ────▶（和暂存区比）              │
         git diff --cached ────────────────────▶（和 HEAD 比）
区域是什么物理位置
工作区你在编辑器里看到、改的文件磁盘上的文件本身
暂存区“下一次提交的清单”，可以只挑一部分.git\index
提交区一条条不可变的快照.git\objects

3. 命令卡（今天实际用过的）

命令作用动不动数据
git status一次比较三个区，分栏显示只读
git add <文件>工作区 → 暂存区改暂存区
git commit -m "说明"暂存区 → 提交区，生成一条记录改历史
git log --oneline历史，每条一行只读
git diff工作区 vs 暂存区只读
git diff --cached暂存区 vs HEAD（下次提交会包含什么）只读
git diff HEAD~1上一条提交 vs 当前 HEAD只读
git restore --staged <文件>从暂存区退回工作区，改动保留改暂存区
git restore <文件>丢弃工作区改动，内容丢失改工作区

两条 restore 的区别：前者只是“不提交了”，后者是“改的东西不要了”。

5. 哈希与对象（今天最抽象的部分）

完整哈希：3fcffbd7a0c6b7a9b2713755cfcde895096b345e（SHA-1，40 位十六进制）；平时用前 7 位。

三个性质：确定（同输入同输出）、雪崩（改一个字符全变）、单向（推不回去）。

commit 97b26b8
├── tree 745742a      ← 这次的文件清单
│   ├── README.md     → blob ef7b2b0   （内容 "# practice"）
│   ├── data.csv      → blob 9e2bf9c

  • 三份：工作区 1、暂存区 1、提交区 0。
